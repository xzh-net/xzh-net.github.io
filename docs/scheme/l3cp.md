# 什么是三级等保？

## 一. 核心变化

中国网络安全等级保护制度（简称“等保”）经历了从 1.0 到 2.0，再到行业发展趋势三个阶段的演变。


| 维度 | 等保 1.0（2007 年起） | 等保 2.0（2019 年起） |
| :--- | ---- | :--- |
| **全称** | 信息安全等级保护 | 网络安全等级保护 |
| **顶层依据** | 《计算机信息系统安全保护条例》 | 《网络安全法》 |
| **性质** | 行政要求 | 法律义务（不合规即违法） |
| **覆盖范围** | 主要看软件应用系统 | “一个中心、三重防护”：<br/>• **安全管理中心**：集中管控、审计、预警<br/>• **安全通信网络**：网络架构、传输加密、边界防护<br/>• **安全区域边界**：访问控制、入侵防范、恶意代码防护<br/>• **安全计算环境**：身份鉴别、访问控制、数据完整性/保密性<br/>• **管理层面**：制度、机构、人员、建设、运维五大环节 |
| **测评对象** | 传统信息系统 | • **技术对象**：<br/> - 物理环境：机房、机柜、门禁、防火、防雷、供电等<br/> - 网络设备：路由器、交换机、负载均衡器等<br/> - 安全设备：防火墙、IDS/IPS、WAF、日志审计、堡垒机等<br/> - 计算设备：服务器（含OS、数据库）、终端、工控机、云主机等<br/> - 应用系统：业务平台、网站、办公系统、移动App等<br/> - 数据对象：存储、传输、处理中的敏感数据（如个人信息、金融数据）<br/>• **管理对象**：<br/> - 制度文档：安全策略、操作规程、应急预案、记录表单等<br/> - 人员角色：安全主管、运维人员、普通用户、第三方服务商等 |
| **测评方式** | 打分制 | 定性判定（符合/基本符合/不符合） + **重大风险隐患一票否决** |

## 二. 核心要点

### 定位与定级

根据规定，等级保护对象的安全保护等级共分五级。其中：

- **第一级**：受到破坏后，仅对公民、法人和其他组织的合法权益造成损害
- **第二级**：受到破坏后，对公民、法人和其他组织的合法权益产生严重损害，或对社会秩序和公共利益造成损害
- **第三级**：受到破坏后，**对公民、法人和其他组织的合法权益产生特别严重损害，或对社会秩序和公共利益造成严重损害，或对国家安全造成损害**
- **第四级**：受到破坏后，对社会秩序和公共利益造成特别严重损害，或对国家安全造成严重损害
- **第五级**：受到破坏后，对国家安全造成特别严重损害

第三级又称为 **“监督保护级”** ，属于**重点监管对象**，是绝大多数政企单位面临的**核心合规红线**。其适用场景广泛——医院HIS系统、智慧政务平台、金融业务系统、教育云平台等。三级定级流程严格，需经过初步定级、专家评审、主管部门审核及公安机关备案。

### 安全要求

#### 1. 身份鉴别

- **用户身份要唯一**：不能两个账号共用一份凭据；管理员账号不能跟普通账号混用。
- **鉴别信息要有复杂度并定期更换**：建议 8 位以上，必须同时包含大小写字母、数字、特殊符号，3~6 个月强制改一次。
- **登录失败处理 + 会话超时**：连续 5 次失败必须锁定账号（一般 20 分钟），30 分钟无操作自动登出。
- **远程管理传输加密**：应采用符合国家标准的密码技术（如TLS/HTTPS），若涉及国密合规要求，需同步满足SM2/SM4等算法要求。
- **双因子认证**：必须采用两种或以上鉴别方式的组合，比如密码 + 短信验证码、密码 + USB-Key、密码 + 证书。

#### 2. 访问控制

- **用户和权限要按需分配**：不能「全员超管」。
- **默认口令必须修改**：初次登录强制改密。
- **默认账号必须被重命名或删除**：默认账号必须被**禁用、重命名或严格限制权限**。
- **三权分立**：系统管理员、安全管理员、审计管理员，三个角色的权限要互相独立、互相制衡。系统管理员不能查审计日志，安全管理员不能改系统配置。

#### 3. 安全审计

- **审计要覆盖每一个用户**：不能漏掉任何账号的关键操作。
- **审计内容要全**：重要业务行为（增删改查）、安全事件（登录失败、权限变更）、系统异常都要落库。
- **审计记录不能被删/改**：即便是管理员也不能直接清日志。
- **审计记录保存周期不少于六个月**，且要定期备份到独立的介质。

#### 4. 通信安全

##### 4.1 数据完整性

应采用**密码算法**保证通信过程中数据的完整性，防止数据被篡改。

- 存储中的重要数据要用 SM3、SHA-512 等算法做哈希校验。
- 传输中的数据要保证完整性，常用 HMAC 或者签名机制。
- 上传文件限制大小、扩展名白名单、MIME 类型校验、内容嗅探（防止改后缀名）。
- 数据有效性校验，必须在服务端进行，前端校验仅作为辅助。需具备防范 SQL 注入、XSS、CSRF 等攻击的能力。

##### 4.2 数据保密性

**完整性保护**：应采用**密码技术**保证通信过程中数据的完整性，防止数据被篡改。

- 存储敏感数据要用 SM2、SM4 加密。
- 数据展示时要做脱敏（手机号中间四位 `*`，身份证留头留尾）。

#### 5. 备份恢复

- **本地备份**：每日全量/增量备份，确保数据可追溯。
- **异地备份与容灾**：应具备异地备份能力，并宜根据业务连续性要求建立异地容灾机制，防止单点故障导致数据永久丢失
- **高可用部署**：关键业务建议采用集群、负载均衡及故障自动切换机制，确保业务连续性。

#### 6. 剩余信息保护

- **内存/硬盘清除**：用户鉴别信息所在的存储空间（无论是内存还是硬盘）被释放或再分配给其他用户前，必须**确保其中的数据被完全清除**
- **文件/目录清除**：系统内的文件、目录和数据库记录等资源被释放或重新分配前，也必须**完全清除**。
